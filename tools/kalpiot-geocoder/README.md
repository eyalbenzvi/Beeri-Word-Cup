# גיאוקודינג לקובץ הקלפיות

הוספת קואורדינטות WGS84 לכל שורה בקובץ הקלפיות של ועדת הבחירות המרכזית
(`קלפיות.xlsx`, גיליון `DataSheet`, 12,525 שורות).

## התקנה

```bash
pip install pandas openpyxl requests pyproj
```

## הרצה

```bash
# 1. בדיקת מנועים על כתובות ביקורת (מומלץ לפני ריצה מלאה)
python geocode_kalpiot.py --selftest

# 2. ריצה מלאה — כ-8 דקות
python geocode_kalpiot.py "קלפיות.xlsx"

# 3. ריצת טעימה על 50 כתובות
python geocode_kalpiot.py "קלפיות.xlsx" --limit 50

# 4. דוח בקרת איכות מהמטמון הקיים, בלי קריאות רשת
python geocode_kalpiot.py "קלפיות.xlsx" --report-only
```

הפלט: `קלפיות עם קואורדינטות.xlsx` עם שתי עמודות חדשות בסוף —
`קואורדינטות` (`31.778123, 35.235401`) ו-`דיוק קואורדינטות`.

הריצה שומרת מטמון (`geocode_cache.json`, `city_cache.json`) כל 50 כתובות,
כך שאפשר לעצור באמצע (Ctrl-C) ולהמשיך מאותה נקודה.

## מנועים

| מנוע | תפקיד | הערות |
|---|---|---|
| **GovMap** | ראשי | `https://www.govmap.gov.il/api/search-service/autocomplete` — ללא טוקן. מחזיר `POINT(x y)` ב-**EPSG:3857**. |
| **Nominatim** | גיבוי | מוגבל לבקשה אחת בשנייה (מדיניות OSM), נאכף גלובלית דרך lock. |

> ה-API הישן `es.govmap.gov.il/TldSearch/api/DetailsByQuery` **הוסר** ומחזיר דף
> שגיאה. אם גם ה-endpoint הנוכחי ייפול, `probe_govmap()` יזהה זאת אוטומטית מול
> כתובת ביקורת ויעבור ל-Nominatim (איטי יותר — כ-70 דקות).

## רמות דיוק

| תווית | משמעות |
|---|---|
| `כתובת מדויקת` | הרחוב **ומספר הבית** תואמים לתוצאה |
| `רחוב` | הרחוב תואם אך מספר הבית לא, או התאמה למבנה/מוסד (`מקום קלפי`) |
| `ישוב בלבד` | מרכז הישוב בלבד |
| `לא נמצא` | לא נמצאה תוצאה שעברה אימות — התא נשאר ריק |

## אימות תוצאות — החלק הקריטי

מנוע החיפוש של GovMap הוא **fuzzy**: הוא כמעט תמיד מחזיר משהו, גם כשאין
התאמה אמיתית. בלי אימות מתקבלות שגיאות של עשרות ומאות ק"מ. דוגמאות אמיתיות
שנתפסו בפיתוח:

| שאילתה | מה שהמנוע החזיר | השגיאה |
|---|---|---|
| `ביה"ס בית יעקב הצפון, ירושלים` | `ביה"ס 203 בית אלפא` | ~100 ק"מ |
| `מסילות` (קיבוץ בעמק בית שאן) | רחוב מסילות ב**אילת** | ~330 ק"מ |
| `מפלסים` (קיבוץ בנגב) | רחוב מפלסים ב**פתח תקווה** | ~80 ק"מ |
| `כפר עציון` | רחוב כפר עציון ב**אפרת** | ~6 ק"מ |

לכן `validate_candidate()` אוכפת, לפי סוג השאילתה:

1. **שם הישוב חייב להופיע בתוצאה** — התנאי החוסם העיקרי.
2. **שאילתת ישוב בלבד** מקבלת אך ורק תוצאה מסוג `settlement`. זו הבדיקה
   שמונעת התאמה לרחוב שנקרא על שם אותו ישוב בעיר אחרת.
3. **שאילתת רחוב/כתובת** מקבלת רק `address`/`street`, ורק אם מילות שם הרחוב
   תואמות. מספר בית שאינו תואם מוריד את הדירוג ל`רחוב` במקום `כתובת מדויקת`.
4. **שאילתת מקום** (`מקום קלפי`) דורשת חפיפה של 2+ מילים עם שם המקום.
5. כל תוצאה נבדקת מול גבולות ישראל (lat 29.3–33.5, lon 34.2–35.95).

ב-Nominatim, `display_name` מסונן מ"נפת …"/"מחוז …" לפני ההשוואה — אחרת
תוצאה בקריית ים "עוברת" אימות לחיפה רק בגלל המילים "נפת חיפה".

## סולם הווריאציות

לכל שורה נבנה סולם חיפושים מהמדויק לגס, והראשון שעובר אימות מנצח:

```
רחוב + מס' בית + אות בית, ישוב     → כתובת מדויקת
רחוב + מס' בית, ישוב               → כתובת מדויקת
רחוב (ללא גרשיים), ישוב            → רחוב
מקום קלפי, ישוב                    → רחוב
ישוב                               → ישוב בלבד
```

בנוסף, **שכבת גיבוי**: כל שורה שאף וריאציה שלה לא נפתרה מקבלת את מרכז הישוב
שלה (`city_cache.json`), מסומן `ישוב בלבד (… — גיבוי ישוב)`. זו נקודה אמיתית
ממקור מוסמך, לא הערכה — כך הכיסוי מלא בלי לטעון לדיוק שאין.

## שמירה על הקובץ המקורי

הפלט נכתב דרך `openpyxl` על **עותק של החוברת המקורית**, ולא ב-
`pandas.to_excel`. הסיבה: מסלול `read_excel → to_excel` היה ממיר טיפוסים
(מספרים שלמים לעשרוניים), מוחק את הגיליון השני (`גיליון1`) ומאבד עיצוב.
כך 35 העמודות המקוריות נשארות זהות בית-בבית, ורק שתי עמודות מתווספות בסוף.

## התאוששות משגיאות

* כשל רשת זמני (timeout, 502/504 — שרת GovMap מחזיר אותם לסירוגין) **לא**
  נשמר במטמון כ"לא נמצא", אלא נזרק כ-`TransientError` ומנוסה שוב בריצה הבאה.
  זה מונע הרעלת מטמון בכשלים חולפים.
* עד 3 ניסיונות לכתובת עם השהיה מכפילה (1.5s / 3s / 6s).
* `--workers` שולט במקביליות (ברירת מחדל 8). ב-Nominatim נאכף `workers=1`.
